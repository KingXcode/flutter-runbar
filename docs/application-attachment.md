# 关联运行中的 Flutter App

项目与应用监听是两个独立来源，共用日志 / 网络查看区域。项目绑定源码目录并拥有启动的命令；应用监听绑定 App 身份，仅拥有与 VM Service 的连接，不拥有目标进程。

## 使用与状态

1. 侧栏底部选择「连接 App」，列表只显示已识别的 Flutter 应用，显示图标、名称及 PID。只有一个候选时自动选中；多个候选时由用户选择。仅检查所选应用的服务，刷新和搜索不会扫描全机端口。
2. 选择后自动识别调试地址，成功后直接点「连接」。失败时可点「重新识别调试地址」，或在可选输入框中粘贴完整的 DevTools / VM Service 链接。始终核对 `getVM.pid` 与选中进程，必要时通过 Flutter 服务能力进一步识别。
3. 连接后的顶部显示应用名、状态、热重载、热重启、DevTools 和「断开连接」，不显示源码目录与命令栏。日志及网络页可继续使用搜索、筛选、跟随和本地缓存。热更新按钮按实际服务能力启用，禁用时悬停可查看原因。
4. 每次连接产生独立的监听记录。断开后可离线查看；再次连接或 App 重启会产生新记录，历史仍按应用归类。
5. 断开、退出 Runbar、App 退出及连接中断都会收尾本地记录。退出 Runbar 不会退出监听目标，也不根据历史 PID 自动连接、激活或终止进程。

侧栏保存的是 Bundle ID 与规范化的安装路径，不以 PID 作为永久身份；同 Bundle ID 的不同安装路径分别管理。重新添加已移除的应用时，能够复用历史中的相同应用身份。一个应用身份同时保留一个连接，避免重复采集。

## 发现与认证

- 候选列表通过 App 内的 Flutter 框架识别，只包含 Flutter App（包括 Flutter 菜单栏 App）。框架存在不代表一定开放调试服务，Release 版本通常仍无法连接。
- 自动连接并行尝试本次 Runbar 已知的完整 VM 地址、所选 PID 的 TCP 监听端口、本机公告的 Dart VM 服务和同一 Flutter 启动器的 DDS 参数。每组最多检查 16 个候选地址，兼容 IPv4 / IPv6 回环；单次 HTTP 返回上限 256 KiB。`lsof` 自身有超时与输出上限，不读取进程环境变量或整份系统日志。
- 本机服务发现使用 DNS-SD 的 `kDNSServiceInterfaceIndexLocalOnly` 浏览和解析 `_dartVmService._tcp`，只读取这台 Mac 已注册的公告，不浏览局域网设备。一次最多解析 32 条公告、返回 16 个地址，3 秒后结束；取消、切换所选 App 或关闭窗口都会释放发现句柄。所选 App 的端口只用于排序：DDS 可能是独立进程，不能据此丢弃其他本机服务地址，最终始终核对 VM PID。
- 部分 macOS Debug App 不发布 Bonjour。此时只读检查所选 App 的直接父进程；仅当它是运行 `flutter_tools` 的 `run` / `attach` 启动器时，才检查其最多 16 个其他直属子进程。只接受官方 Dart `development-service` / DDS snapshot 的 `--vm-service-uri` 参数，并再次核对当前父子关系、上游端口及 VM PID。`ps` / `pgrep` 仅接收指定 PID，单次输出最多 64 KiB、2 秒超时；不读取目标环境、终端历史或所有进程命令行。由 Finder / Xcode 独立启动且没有公告或可识别 DDS 参数时，仍可手动粘贴链接。
- 原始 VM 与 DDS 地址可能不同。先验证原始地址的 `getVM.pid`，然后只读取 `index.html` 的官方 DevTools 重定向头，提取本机服务 URI，不自动跟随页面跳转；每个新地址都重新核对 PID，最多处理 3 个地址，拒绝循环及 HTTPS 降级。手动填写的原始 VM 链接也走这条流程，避免 HTTP 识别成功后 WebSocket 被重定向而连接失败。
- 开启认证的 VM 需要完整认证路径。本机公告提供 `authCode` 时据此组装地址；只有端口且没有公告 / 已知链接时，仍可能需要手动粘贴。不会猜测令牌、关闭认证或修改目标启动参数。
- 仅连接 loopback，保留认证路径，不自动跟随重定向。连接前后重新核对所选 App 的启动身份，防止 PID 回收后误关联。
- VM / DevTools 地址只保存在本次连接的内存状态，不写入应用配置或监听记录元数据。目标自行打印的内容仍会按正常日志规则保存。

## 日志、网络与 DevTools

日志使用 VM Service WebSocket 的 `Stdout`、`Stderr`、`Logging` 流，不截取另一个进程的终端管道。只接收订阅后的事件；某些流不受支持时提示实际能力，网络采集可独立工作。`developer.log` 的截断字符串会通过受限的 `getObject` 读取，超过 64K 字符仍提示截断，不声称拿到了原本不存在的历史日志。

单条 VM 事件上限 1 MiB；待落盘缓冲最多 64 KiB，约 100 ms 批量写入 `output.raw` 和接收时间索引。大块数据直接写盘；界面按既有窗口读取，不保留整份事件列表。写盘失败会结束监听并标注记录可能不完整。网络使用现有的摘要分页、正文缓存和容量限制，范围见 [网络采集说明](devtools-network-capture.md)。WebView、未接入 profiling 的原生网络库与 WebSocket 不因本功能自动获得支持。

DevTools 优先使用用户输入的完整本机页面链接；只有点击 DevTools 时才启动本机 SDK 的前端，复用「设置」中的额外 PATH。缺少 SDK 会明确提示。前端服务由 Runbar 自己拥有，正常退出时停止；与目标 App 的生命周期分开管理。

## 关联 App 的热更新

热重载与热重启复用原 IDE / `flutter run` 注册的 Flutter 编译服务，无需改动目标项目。关联的是运行中的 App，Runbar 没有它的源码目录和编译器上下文，所以独立 VM 的 `reloadSources` / `reassemble` 不作为替代方案，也不向外部终端或目标进程注入按键、信号。原调试工具需保持连接，并提供对应能力；Debug 模式本身不是能力保证。若自动发现的地址不包含这些服务，可使用原调试工具公布的完整 DevTools / VM Service 链接重新关联。

- 单独使用有大小上限的 VM WebSocket，监听 `Service` 的注册与注销事件；只调用别名为 `Flutter Tools` 的服务公布的完整方法名。多个同类编译服务并存时禁用该操作，避免选错提供方。
- 热重载重新查询当前 Flutter 视图的 isolate，要求目标唯一；热重启调用工具的完整重启服务。每次操作再次核对 `getVM.pid`，不复用历史 isolate。热重载保留状态，热重启重置状态，原生代码修改仍需重新构建启动。
- 操作期间禁用重复点击，以工具 RPC 的成功或失败结果为准，编译详情在原 IDE / `flutter run` 输出中查看。等待超过 120 秒后关闭热更新连接并提示人工确认结果，不自动重试；已发出的操作不会因 Runbar 断开而保证取消。
- 连接中断只清除热更新能力，日志和网络连接独立收尾；显式断开、App 退出或 Runbar 退出时关闭所属控制连接。回调按本次连接身份隔离，不更新下一次连接的按钮状态。
- 单条事件最多 1 MiB、最多 4 个等待中的 RPC、最多 16 个服务登记，不缓存服务事件历史。认证链接与原始 RPC 错误内容不会写入记录或显示到错误弹窗。
